🔀 Git y
GitHub:
Control de Versiones

Repositorios, colaboración, ciencia abierta y GitHub Pages — la infraestructura invisible detrás de la ciencia moderna

// GitGitHubControl de VersionesOpen Science

Imaginá que trabajás en un código de simulación durante meses. En algún momento algo deja de funcionar y no sabés exactamente cuándo ni por qué. Sin Git, eso significa revisar a mano todos los cambios que hiciste. Con Git, en un comando podés ver exactamente qué líneas cambiaste cada día, volver a cualquier versión anterior en segundos y comparar resultados entre versiones. Git es un sistema de control de versiones: una herramienta que registra la historia completa de todos los cambios en un proyecto.

GitHub es la plataforma en la nube donde se alojan los repositorios Git. Es a Git lo que Gmail es al correo electrónico: no son lo mismo, pero se usan juntos. GitHub además agrega colaboración (múltiples personas trabajando en el mismo proyecto), issues para reportar problemas, y una funcionalidad especialmente útil para físicos y docentes: GitHub Pages, que permite publicar un sitio web estático directamente desde un repositorio — exactamente lo que usa este sitio.

¿Para qué sirve en física?

En física, Git resuelve problemas concretos: mantener versiones de scripts de análisis de datos, colaborar en código de simulación con otros integrantes del grupo, publicar código junto con los papers (reproducibilidad científica) y alojar sitios web de divulgación o docencia. El movimiento de ciencia abierta (open science) usa Git como infraestructura central: los repositorios con código y datos de papers permiten que cualquier persona reproduzca los resultados.

Usos de Git/GitHub en física y docencia: · Versionar scripts Python de análisis de datos · Colaborar en simulaciones numéricas · Publicar código que acompaña papers (reproducibilidad) · Hospedar sitios web con GitHub Pages (gratis) · Mantener apuntes, guías y material docente · Distribuir código de laboratorio a estudiantes

La analogía del cuaderno de laboratorio: Un cuaderno de laboratorio registra cada medición, cada cambio de procedimiento y cada observación con fecha y contexto. Git hace exactamente eso con el código: cada commit es una entrada del cuaderno que dice "el día X, cambié esto por esta razón". La diferencia es que con Git podés volver a cualquier entrada anterior y retomar el experimento desde ese punto exacto.

Instalación

# Linux (Ubuntu/Debian) sudo apt install git # macOS (si no está instalado ya) brew install git # o simplemente escribir "git" en terminal: macOS ofrecerá instalarlo # Windows # Descargar Git for Windows desde: https://git-scm.com/download/win # Incluye Git Bash (terminal Linux-like) # Configuración inicial (una sola vez) git config --global user.name "Tu Nombre" git config --global user.email "tu@email.com" # Verificar instalación git --version

Ejemplo de uso: flujo de trabajo típico

El flujo básico de Git se resume en cuatro operaciones: inicializar un repositorio, agregar archivos al área de seguimiento, confirmar los cambios con un mensaje descriptivo, y subir al repositorio remoto en GitHub. Una vez dominadas estas cuatro operaciones, el 80% del uso diario está cubierto.

# --- Crear un repositorio nuevo --- mkdir simulacion-pendulo cd simulacion-pendulo git init # inicializar repositorio Git local # --- Flujo de trabajo diario --- # 1. Ver el estado actual git status # 2. Agregar archivos al área de preparación (staging) git add pendulo.py # archivo específico git add . # todos los archivos nuevos/modificados # 3. Confirmar cambios con mensaje descriptivo git commit -m "Agrego integración RK4 para el péndulo doble" # 4. Ver historial de commits git log --oneline # --- Conectar con GitHub --- # (primero crear el repositorio en github.com) git remote add origin https://github.com/usuario/simulacion-pendulo.git git push -u origin main # --- Volver a una versión anterior --- git log --oneline # ver hash de commits git checkout abc1234 # ir a esa versión git checkout main # volver al presente # --- Trabajar en una nueva función sin romper lo que funciona --- git branch feature-amortiguamiento git checkout feature-amortiguamiento # ... hacés cambios ... git commit -m "Agrego término de amortiguamiento" git checkout main git merge feature-amortiguamiento

El .gitignore: Ciertos archivos no deberían versionarse — resultados intermedios, archivos de configuración local, datos crudos pesados, archivos compilados. El archivo .gitignore en la raíz del repositorio lista los patrones a ignorar. Para Python, lo mínimo es ignorar __pycache__/, *.pyc y .ipynb_checkpoints/. GitHub ofrece plantillas de .gitignore para cada lenguaje al crear un repositorio.

GitHub Pages: tu sitio web gratis desde un repositorio

GitHub Pages convierte cualquier repositorio con archivos HTML/CSS/JS en un sitio web público accesible en usuario.github.io/repositorio. Sin servidores, sin costos, con actualización automática cada vez que hacés push. Es exactamente la infraestructura que usa Mundo Quarks. Para activarlo: Settings → Pages → Source: Deploy from branch → main. Ideal para portafolios, materiales docentes y sitios de divulgación.

Git es una de esas herramientas que parece innecesaria hasta el día que te salva. No hace falta entender todos sus detalles internos para empezar a usarlo: con init, add, commit y push ya tenés control de versiones funcional. Y una vez que el hábito está instalado, es difícil imaginar trabajar en cualquier proyecto de código o escritura sin él. En ciencia, donde la reproducibilidad es fundamental, Git es infraestructura tan básica como el cuaderno de laboratorio.
